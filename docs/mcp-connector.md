# קונקטור MCP — רשימות קניות ב-Claude

מאפשר לכל משתמש של האפליקציה לנהל את רשימות הקניות שלו ישירות משיחה ב-Claude,
בלי לפתוח את האפליקציה. הקונקטור גנרי: כתובת אחת משרתת את כל המשתמשים, וכל אחד
מתחבר עם חשבון Google שלו ורואה רק את מה ששותף איתו.

## למשתמש — איך מתחברים

**כתובת הקונקטור:**
```
https://xgihixrhosbxyloeoxnv.supabase.co/functions/v1/mcp-shopping
```

1. ב-Claude: Settings → Connectors → Add custom connector → הדבק את הכתובת.
2. ייפתח דפדפן — התחבר עם Google (אותו חשבון שבו אתה משתמש באפליקציה).
3. יופיע מסך אישור בעברית. ודא שכתוב "תוחזר אל: **claude.ai**", ואשר.

זהו. מעכשיו אפשר לכתוב ל-Claude "מה יש ברשימת הקניות?" או "תוסיף חלב ולחם".

זמין גם בתוכנית החינמית של Claude (מוגבלת לקונקטור מותאם אחד).

**כדי להתנתק:** ב-Claude, Settings → Connectors → הסר את הקונקטור. (ניתוק מצד
האפליקציה עדיין לא קיים — ראה "פערים ידועים".)

**חשוב:** הקונקטור לא נותן גישה לרשימות שלא שותפו איתך. שיתוף רשימה נעשה
באפליקציה כרגיל (כפתור השיתוף), ומשם ההרשאות זהות: מה שמשותף — נגיש, מה שלא — לא.

## מה הקונקטור יכול ומה לא

| כלי | מה עושה |
|---|---|
| `get_lists` | הרשימות הפעילות שלי + ששותפו איתי, עם מספר פריטים פתוחים |
| `get_list_items` | פריטי רשימה: שם, כמות, יחידה, הערות, מחלקה, האם בעגלה |
| `add_item` | הוספת פריט; מתאים אוטומטית למוצר בקטלוג (איות ומחלקה נכונים) |
| `set_item_in_cart` | סימון/ביטול "בעגלה" |

**הכלים לא כוללים:** מחיקת פריטים או רשימות, יצירת רשימות, שינוי שיתופים,
סיום קנייה. אלה נשארו באפליקציה בכוונה.

**אבל שים לב — זו הגבלה של הכלים, לא של ההרשאה.** הטוקן ש-OAuth מנפיק הוא זהות
מלאה של חשבונך באפליקציה, ולא מוגבל טכנית לארבעת הכלים. לכן יש לאשר רק קונקטורים
שאתה סומך עליהם, ולוודא במסך האישור שכתובת ההחזרה היא באמת של Claude.

## למתחזק — ארכיטקטורה

```
Claude  ──MCP over HTTP──▶  Edge Function: mcp-shopping
                                   │  anon key + ה-JWT של המשתמש
                                   ▼
                            schema "shopping" — RLS אוכף כמשתמש
```

- **אימות:** Supabase Auth משמש כ-OAuth 2.1 identity provider. הפונקציה נפרסת עם
  `verify_jwt=false` (ריקוד ה-discovery חייב לענות לבקשות לא מאומתות) ומאמתת את
  ה-JWT בעצמה, מקומית.
- **דף האישור:** `src/components/OAuthConsent.tsx`. `App.tsx` מזהה
  `?authorization_id=` בכתובת (אין router באפליקציה), שומר ב-`sessionStorage`
  כדי לשרוד את סבב ההתחברות ל-Google, ומנקה מה-URL.
- **בדיקות:** `node scripts/mcp_test.mjs` — 30 בדיקות מול הפונקציה החיה, כולל
  בידוד בין משתמשים ודחיית טוקן אנונימי. דורש `.env.local`.

### הפעלה ראשונית (חד-פעמי, בדשבורד)

הקוד פרוס ונבדק, אבל הקונקטור לא יעבוד עד שהצעדים האלה יבוצעו. סדר הצעדים
מחייב — אי אפשר לרשום קליינט לפני שהשרת מופעל.

1. **Authentication → Providers → Anonymous sign-ins → כבה.** האפליקציה לא
   משתמשת בזה; כל עוד זה פעיל, כל אחד יכול לייצר חשבון בלי פרטים.
2. **Authentication → OAuth Server → הפעל.** Dynamic client registration נשאר
   **כבוי** (ראה אינווריאנט 8). Authorization Path = `/`, ו-Site URL תחת
   URL Configuration צריך להיות `https://avitantal.github.io/ShoppingList/`.
   אימות: `https://<ref>.supabase.co/.well-known/oauth-authorization-server/auth/v1`
   מחזיר JSON ולא `feature_disabled`.
3. **Authentication → OAuth Apps → Add a new client:** שם `Claude`, סוג
   `Public`, ו-Redirect URI המדויק שמופיע במסך הוספת הקונקטור ב-Claude
   (התאמה מלאה, בלי wildcards). שמור את ה-Client ID לטבלה שלמטה.

### אינווריאנטים אבטחתיים — אל תשבור אותם

מקורם בסקירת אבטחה; כל אחד מהם נבדק בחבילת הבדיקות או נאכף בקוד:

1. **לעולם לא service-role key** בפונקציה הזו. ה-RLS הוא גבול האכיפה היחיד.
2. **אימות JWT מקומי** מול JWKS (ES256), כולל בדיקה מפורשת של
   `role === 'authenticated'` — טוקן `service_role` כ-Bearer היה עוקף RLS לגמרי.
3. **קליינט Supabase נוצר בתוך ה-handler, בכל בקשה.** ה-isolates ממוחזרים בין
   משתמשים; קליינט ברמת המודול היה מגיש בקשה של משתמש אחד עם הטוקן של אחר.
4. **`set_item_in_cart` מעדכן projection קשיח** (`{ is_in_cart }`) — מדיניות
   ה-RLS מתירה לחבר רשימה לעדכן כל עמודה, אז אסור לפזר ארגומנטים מהקליינט.
5. **טקסט מהרשימות ומהקטלוג נעטף ב-`<untrusted-user-data>`** ותיאורי הכלים
   אומרים במפורש שזה דאטה ולא הוראות — התוכן נכנס להקשר של Claude שבו יושבים
   גם קונקטורים אחרים של המשתמש (Gmail, Drive).
6. **שגיאות Postgres ממופות למחרוזות עברית גנריות**; ה-Authorization header
   לעולם לא נרשם ללוג.
7. **דף האישור:** frame-busting ב-JS (GitHub Pages לא יכול לשלוח
   `X-Frame-Options`), ולידציית `https:` בלבד על כתובת ההחזרה,
   `skipBrowserRedirect: true` — בלעדיו ה-SDK מנווט לבד ועוקף את הוולידציה —
   ולחיצה מפורשת תמיד, גם כשכבר אושר בעבר.
8. **רישום דינמי של קליינטים (DCR) נשאר כבוי.** מסך האישור הוא היעד של פישינג,
   לא ההגנה מפניו; שם הקליינט הוא טקסט שהתוקף בוחר, ולכן ה-host של כתובת
   ההחזרה הוא סימן הזיהוי המוצג.
9. **לא להגדיר את ה-GUC `app.service_role_key`** — `refresh_products_now` קורא
   ממנו; אם הפונקציה הזו תוחזר לשימוש, להעביר ל-Supabase Vault.

## סיכונים פתוחים בפרויקט (לא נובעים מהקונקטור)

נמצאו בסקירת האבטחה שאחרי המימוש. שלושתם קיימים בלי קשר לקונקטור, אבל הוא
מרחיב את מעגל האנשים שמחזיקים תפקיד `authenticated`, ולכן שווה לטפל:

1. ~~`set_department_override` פתוח לכל משתמש מחובר~~ — **תוקן במיגרציה 0021.**
   הכתיבה למיפוי המחלקות המשותף מוגבלת ל-`app_admins`. משתמש רגיל לא איבד
   כלום: האפליקציה נופלת אוטומטית למנגנון העקיפה המקומי, כך שהפריט עדיין עובר
   למחלקה שבחר — רק שהבחירה שלו כבר לא משנה את הקטלוג לכל השאר. להוסיף מנהל:
   `insert into shopping.app_admins (user_id) values ('<uuid>');`
2. **כניסה אנונימית מופעלת** ברמת הפרויקט והאפליקציה לא משתמשת בה כלל. כדאי
   לכבות: Authentication → Providers → Anonymous sign-ins. הקונקטור כבר דוחה
   טוקנים כאלה. כל עוד זה פעיל, כל הרצה של חבילת הבדיקות יוצרת משתמש אנונימי
   אחד; אחרי הכיבוי הבדיקה עוברת לענף "הנתיב סגור" ומפסיקה ליצור.
3. **טבלאות הקטלוג עדיין נושאות הרשאות כתיבה ל-`authenticated`.** לא מזיק
   היום (אין policy מתירני, אז כתיבה נוגעת ב-0 שורות), אבל policy רשלני אחד
   מפריד בין זה לבין הרעלת קטלוג.

## פערים ידועים

- **אין ניתוק מצד האפליקציה.** משתמש יכול להסיר את הקונקטור ב-Claude, אבל אין
  מסך "נתק את Claude" באפליקציה. ה-SDK חושף `listGrants`/revoke — בסיס טוב
  לתוספת עתידית.
- **OAuth 2.1 Server של Supabase הוא בבטא.** חינם בכל התוכניות בתקופת הבטא.
